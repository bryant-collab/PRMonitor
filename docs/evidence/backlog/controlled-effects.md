## Publication

its actual F11 claim/hold and F13 before/after attribution, and seeds clearly
historical passed validation and a human response draft. Only F22 remote-head
reads and F23 commit/push/response ports are controlled for this exact bundle.

The real first approval refresh changes the candidate and returns
CANDIDATE_CHANGED. No effects run. This exposed incorrect renderer success copy;
the renderer now reports the actual refusal and invalidates old acknowledgements.
Explicit navigation/reread exposes the fresh candidate; a new acknowledgement
then durably approves it without publication effects. Publish produces a
controlled uncertain push. Reconcile confirms code publication, encounters a
failed response, and exposes response-only retry. Retry reaches PUBLISHED;
terminal replay produces no additional effects. Counts are one commit port,
one push port, one push reconciliation and two response attempts. The F11 hold
is released and actual owned source bytes remain unchanged.

## Synchronization

`conditional-sync` gives three historical F25 results their own registered F13
worktrees and actual before/after attributed snapshots. Controlled F27 ports
return exact-input remote freshness, commit/push uncertainty/reconciliation,
and one new-preparation acknowledgement. No actual Git publication runs.

Blank answer is disabled. Submit answer, Submit direction, Confirm manual edit
and Retry resolution each save one versioned historical intent and retain
consultation history. The historical handoff has no active AI operation, so these
actions start no new budget/provider call. Actual remote/worktree refresh exposes
choices. Keep and Cancel preserves bytes; Clear AI restores the actual owned
worktree and persists CLEAN evidence. An owned manual edit remains protected from
Clear All. Restoring the exact prior attributed fixture bytes and explicitly
refreshing evidence permits acknowledged Clear All; terminal Discard retains
the four new history entries.

The separate ready result requires complete-diff acknowledgement before durable
approval. Its uncertain push reconciles to PUBLISHED with one commit/push port
and no extra push on replay. The third result's explicit re-evaluation records

does not establish a newly prepared F25 batch; actual preparation/persistence
and failure handling have separate owning F24/F25/F26 aggregate tests.

## Settings

`conditional-preferences` covers malformed provider JSON without persistence,
disabled-provider classification and explicit revalidation without invocation,
all five policy presets in an isolated profile followed by restoring the original,
invalid/stale policy refusals, invalid turn bounds/root/timers without persisted
changes, and a valid explicit retry. All saved policies retain operation-owned
scope and false publication authority. No host/user policy or provider is changed.

Physical dialogs, Windows scaling, spoken screen-reader output and shipping
installer identity remain explicitly unverified in the [finite acceptance ledger](remaining-acceptance.md).
These controlled ports establish native control/guard/history behavior, not live
model/GitHub adapter success or production sandboxing. Production artifact smoke
separately enforces the sandbox. No deadline, assertion or security gate is weakened.
