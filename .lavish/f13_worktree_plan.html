Core boundary

Where F13 sits in the operation flow

deterministic only

The trust boundary is intentionally narrow: F13 can create and inspect local operation state, but it cannot decide semantic fixes or publish anything. Every downstream effect rechecks the actual worktree.

Locked decisions

What the plan commits to

  • One operation-owned path per review, conversation, or synchronization operation.
  • The developer clone is read-only; missing clone setup blocks work instead of triggering an implicit clone.
  • prBaseSha, prHeadSha, and worktreeBaselineSha retain distinct meanings.
  • AI-only cleanup is deterministic three-way removal and fails closed on overlap.
  • Clear All removes tracked/staged and non-ignored untracked files only; ignored artifacts remain visible.

Review attention

Decisions worth annotating

The semantic PRD linter found no definite misses, but three requirements remain low-confidence: persisted path visibility after root changes, post-clear evidence, and bounded F09 diagnostics. The document contains explicit acceptance language for each; reviewers can confirm or refine it before implementation.

Coverage: application coverage also passes with review. F13 is primary for isolation/attribution and shared for diff, root, open/reveal, and synchronization evidence.

Who owns what
