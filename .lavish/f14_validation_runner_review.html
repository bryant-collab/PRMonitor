Comparison

What exists → what F14 adds

F00 already defines the safe contract. F14 closes the execution and durability gap.

Current foundation F00 contract

  • Resolves one trusted profile and freezes its content hash.
  • Prepares a shell-free executable/argument command.
  • Bounds and redacts streams without spawning a process.
  • Defines lifecycle transitions, manual evidence, and consumer parity.

Target behavior F14 runner

  • Rechecks the live F13 worktree, then persists intent before launch.
  • Runs real commands sequentially with process-tree control.
  • Persists phase-specific exit evidence through F03 and emits F09 diagnostics.
  • Survives renderer closure/restart without replaying an incomplete command.

Core relationship

Where can a validation result become trusted?

Only after the input is snapshotted, the worktree is re-inspected, and the observed process outcome is durably recorded.

Before launch

F00 trust + snapshot, F13 actual state, F03 durable intent.

During launch

Structured args, shell disabled, bounded streams, five-second termination grace.

After launch

Phase-specific evidence, manual labels, restart-safe result, F09 diagnostic.

Implementation plan

Six slices, one vertical handoff

Each slice leaves a visible, testable result and names the failure boundary before moving downstream.

01 · ADMITF00/F13/F03

Snapshot + owned worktree

Reject stale/unowned worktrees; persist intent before any spawn; make no-profile a durable warning.

02 · EXECUTEshell: false

Structured process boundary

Run exact executable/argument arrays with controlled environment and Windows resolution.

03 · SEQUENCEphase-aware

Baseline / post-change

Preserve declared order, stop after the first non-pass, and keep phase evidence separate.

04 · RECOVER5 sec grace

Timeout + restart

Terminate the process tree deterministically; renderer close is a no-op; restart never resumes silently.

05 · EVIDENCEredact first

Output + manual checks

Bound streams, preserve truncation metadata, record human attestations, and expose no-safe-command.

06 · HAND OFFreview + sync

Durable consumer parity

Reconstruct results after restart, emit F09 diagnostics, and give review/sync one shared read contract.

Review before implementation

Risks are explicit; product choices are resolved

No new product decision is required to start implementation. These are verification risks the plan calls out as gates.

Windows process trees

Child-process behavior can vary across shells and descendants. The plan requires real Windows fixtures plus an injected process-control port, with graceful termination before force termination.

Output safety under pressure

Secrets and multi-byte output can cross chunk boundaries. The plan reuses F00/F09 streaming redaction and scans persisted, IPC, activity, and evidence surfaces.

Phase ambiguity

A command tagged both must not blur baseline and post-change meaning. The result model records configured and executed phase and keys evidence to the run.

Uncertain restart state

A process may stop after a durable intent but before a terminal result. F03 reconciliation and F00 restart finalization produce interrupted evidence instead of an optimistic retry.
