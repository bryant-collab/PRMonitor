Ownership at a glance

F25 owns

Batch/operation intake, independent per-PR execution, exact merge evidence, no-op/clean/conflict classification, post-change validation handoff, durable result and reason data.

Downstream owns

F26 owns semantic conflict resolution. F27 owns result review, stale detection, discard/re-evaluation, merge-commit creation, non-force push, and publication recovery.

Never granted

No commit, push, force push, GitHub response, conversation resolution, review approval, AI-provider publication, or automatic branch synchronization authority.

Primary-state rule

Synchronization remains an overlay. It never rewrites the PR’s primary review state or releases an active Review Bundle hold.

01 · Intake

Persist one batch and one operation per eligible PR before any local effect; retain skipped rows and make replay idempotent.

02 · Preparation

Exact worktrees

Materialize exact source/head commits, create distinct F13 worktrees, compute merge base, and persist both-side evidence.

03 · Git

No-op / clean / conflict

Classify ancestry, run an explicit no-commit merge, inspect actual state, and hand real conflicts to F26.

04 · Truth

05 · Recovery

Sibling isolation

06 · Handoff

Conformance gate

Prove no AI/publication capability leaks, accessibility semantics, exact coverage, and safe F26/F27 contracts.
